# 测试清单：游戏本体备份（v0.3 按部分备份）和云盘测速

新增：设置页「云盘测速」、游戏详情页「游戏本体」卡片（备份、更新、恢复、版本、备份设置）、Steam 插件里本体缺失时的「从云端安装」。

游戏按部分备份（[plan-game-backup.md](plan-game-backup.md) 第 8 节）：**程序**（模拟器、重编译程序）、**游戏文件**（光盘镜像、ROM、游戏文件夹、更新、DLC）、**设置和 mods**、**密钥和固件**（勾选才备份）。规则不认识的游戏整个文件夹一起备份（卡片上写「整个文件夹」）。所有游戏共用云端的数据块：同一个模拟器、同一个 ROM 只存一份。

## 构建和安装

在这个分支的工作目录里构建（`secrets.local.env` 不在 git 里，先从主目录复制一份过来）：

```powershell
cd C:\Users\Chiip03\Documents\Projects\Ludonimbus\.claude\worktrees\game-backup-09ab8a
Copy-Item ..\..\..\secrets.local.env . -ErrorAction SilentlyContinue
./scripts/build-release.ps1
```

版本号还是 0.5.0，覆盖安装即可。已经装过 Ludonimbus 插件的话，应用启动时会自动换成新插件（`logs` 文件夹的 `steam-plugin.log` 里有 updated the installed Steam plugin），之后重启一次 Steam（插件只在 Steam 启动时加载）。

日志：`%APPDATA%\Ludonimbus\logs\gamebackup.log`（每次备份 / 恢复 / 删除的开始和结果）、`agent.log`（Steam 插件的请求）。云端的数据在云盘 `Ludonimbus` 文件夹下的 `gamebackup\`：`chunks\`（所有游戏共用的数据块）和 `games\<游戏>\versions\`（每个版本的清单）。

这个分支已经合并了 `main`（0.6 的游戏时间、截图、Steam 里的版本列表），可以和 [testing-v0.6.md](testing-v0.6.md) 用同一个安装包测。

**不要用真实游戏做会覆盖文件的测试**：恢复都先恢复到新的临时文件夹；模拟「游戏没了」时把文件夹改名，测完改回来。

## 已经自动验证过的

- 单元测试：切块、块的压缩和校验、清单、扫描和排除、路径安全、各部分的路径（`{program}`、`{content}` …）、版本号（文件夹名、Switch 文件名）、启动参数里路径的改写。
- 本地文件夹和内存里的 WebDAV 服务器上的完整流程（`crates/core/tests/game_backup.rs`），三部分：
  - **普通 PC 游戏（整个文件夹）**：备份 → 没变化时不上传 → 改 100 字节加一个文件后只传几个块 → 恢复后逐字节一致、修改时间一致、存档和日志不在里面、空文件夹还在 → 从恢复出来的文件夹再备份不产生新版本 → 只碰了文件没改内容不产生新版本 → 恢复到已经完整的文件夹什么都不写 → 停止的恢复从断点继续 → 停止的备份只补传缺的块 → 8 MB 以上的大文件没变时不再读 → 保留 2 个版本时清理旧版本和只有它们用的块 → 手动删除后清理 → 另一台设备持有锁时报出它的名字、清理会推迟 → 云端的块损坏时恢复报错 → 恢复后游戏的程序路径指向新位置。
  - **两个共用一个 Cemu 的 Wii U 游戏**：分成程序（Cemu 2.6）、游戏文件（游戏文件夹加上 MLC 里的更新，版本 v208）、设置（这个游戏的 gameProfile）；程序里没有存档、别的游戏的更新、ROM、着色器缓存、keys.txt；勾选后 keys.txt 才作为「密钥和固件」→ 第二个游戏只上传它自己的部分 → ROM 里的大文件改名后再备份什么都不上传 → 恢复到新文件夹（新电脑）后各部分都在原来的相对位置、没备份的东西都不在 → 第二个游戏恢复时本机已有的 Cemu 一个文件都不重写 → 选择保留本机另一个版本的 Cemu 时只恢复游戏自己的部分 → 恢复后游戏的程序和启动参数（游戏的新路径）都改好了 → 删掉一个游戏的全部版本后，另一个游戏的数据还在、还能恢复。
  - **启动器现场编译的重编译游戏**（用 fefw recomp 的规则）：`fefw.exe`、解包后的 `exefs`、`build/` 不备份，程序部分只有启动器并记下它；`fefw.ini` 里 `romfs` 指向程序文件夹外导出的游戏，它和旁边的 `exefs` 算作游戏文件，`fefw.ini` 算作设置 → 恢复到新的程序和游戏文件夹后，编译出来的文件和它们的文件夹都不在；新的 `fefw.ini` 里 `romfs`、`exefs` 指向新位置，原内容留在 `fefw.ini.ludonimbus-bak`；游戏的程序路径指向新位置的 `fefw.exe` → 再修正一次什么都不改。
- 用你本机的游戏做的只读「计算大小」（`game-backup backup <游戏> --dry-run`，不连云盘、不写任何文件）。三个重编译启动器编译出来的东西不备份（Lantern Engine 的程序部分和它的发布包 zip 逐个文件核对过）：

  | 塞尔达 时之笛 Longshot | 103.8 MB（只有启动器，构建好的游戏不备份） | 23.9 GB（.nup） | 1 个文件 |
  | Bloodborne（Lantern Engine 0.9.43） | 431.5 MB | 29.3 GB（CUSA…） | 1 个文件 |

- 测速：本地文件夹和 WebDAV 上四轮都有数据，取消和到时间上限都能正确结束，测试文件全部删掉（`tests/speed_test.rs`）。
- 命令行 `ludonimbus game-backup backup --dry-run / backup / list / check / restore` 在临时数据目录里跑通。
- 浏览器预览（示例数据）里看过测速卡片、「游戏本体」卡片（各部分、备份设置）、恢复对话框（使用本机已有的程序 / 程序装到 / 游戏文件放到）。
- **没验证的**：真正的应用里的进度和事件、Steam 插件在 Steam 里的显示和点击、真实网盘的速度、真实模拟器（Dolphin、Ryujinx、shadPS4、RPCS3 的文件夹布局只按资料写了规则）、Steam 快捷方式的修正。

## 需要在真实环境确认的

### 1. 测速：跳过

你已经确认各云盘都能跑满宽带（上传慢是宽带上行，百度慢是没开会员），不用再跑。设置页的「云盘测速」想顺手点一下也行：能跑完、测试文件删干净就可以。

### 2. 普通 PC 游戏（整个文件夹）

选一个不在 Steam 正版库里、规则不认识的小游戏（绿色版）。

1. 详情页「游戏本体」卡片：标题下显示「文件夹」。点「计算大小」：一行「整个文件夹 · X 个文件，Y」，存档、日志被排除。
2. 「备份到云端」：进度依次是扫描、查看云端、上传（已读取 / 已上传 / 速度 / 剩余时间）、核对、保存版本，完成提示上传了多少。卡片显示最新备份和「整个文件夹 …」。
3. 再点「更新备份」：提示「游戏文件没有变化」。改一个文件后再备份：只上传很少的数据。
4. 备份到一半点「停止」，再点备份：已传的不再传，最后成功。

### 3. 模拟器游戏（按部分）

选一个用 Cemu、Dolphin、Ryujinx、shadPS4 或 RPCS3 启动的游戏（启动参数里有游戏文件的路径）。

1. 卡片标题下显示「程序文件夹」。点「计算大小」：分几行，例如「程序 Cemu 2.x」「游戏文件 v…」「设置和 mods」，各自的文件数和大小。看看是否合理：
   - 程序里没有存档、没有别的游戏的 ROM 和更新、没有着色器缓存；
   - 游戏文件里有这个游戏的光盘镜像或游戏文件夹（Cemu、RPCS3 还有装进模拟器的更新）；
   - 不对的地方请截图告诉我是哪个模拟器、哪个文件。
2. 备份这个游戏。然后备份**另一个用同一个模拟器的游戏**：第二次「已上传」只有那个游戏自己的大小，不再传模拟器。
3. 把这个游戏的光盘镜像（或游戏文件夹里的大文件）改个名字，改启动参数让它指向新名字（或者不改，只看备份），再「更新备份」：几乎不上传。测完改回来。
4. 「备份设置」：取消勾选「程序」后再备份，新版本里没有程序这一部分；勾回来。
5. 「备份设置」里有「也备份密钥、固件、BIOS」（Cemu、Ryujinx、Dolphin、shadPS4、RPCS3 才有）：勾选后「计算大小」多一行「密钥和固件」；不勾时它们不在任何部分里。

### 4. 重编译游戏

选一个重编译游戏（例如 Zelda 64: Recompiled、fefw recomp，或 RecompLauncher 装的）。

1. 「计算大小」：「程序」带版本号（来自发布包文件夹名，如 0.2.7，或程序里的版本信息）。
2. N64Recomp 游戏（Zelda 64、Banjo 等）：「游戏文件」里应该有你第一次启动时选的 ROM（.z64），「设置和 mods」里有它的 `*.json` 和 `mods`。如果没有，告诉我 ROM 实际放在哪里。
3. Longshot、fefw recomp、Bloodborne（Lantern Engine）：数字应该和上面「已经自动验证过的」表格差不多。「游戏文件」是你导出的游戏（.nup、exefs + romfs、CUSA…），不在程序里；程序里没有启动器编译出来的东西（`fefw.exe`、Longshot 构建好的游戏、Lantern 的 `engine-assets`）。
   - 恢复后照常启动：Longshot（启动器）和 Bloodborne（`Bloodborne.exe` 是发布包自带的）由启动器自己编译。fefw 的 Steam 快捷方式直接指向编译出来的 `fefw.exe`，编译之前它不存在，插件会显示「从云端安装」：保持现状，恢复后自己用 `fefw-launcher.exe` 编译一次，之后照常启动。
4. **注意**：Lantern Engine、Longshot、N64Recomp 的设置文件在 `%APPDATA%` / `%LOCALAPPDATA%` 里，恢复时会写回这些真实位置（内容和备份时一样的话不改）。测恢复前先把对应文件夹复制一份，或者只用第 5 节的模拟器游戏测恢复。

### 5. 恢复到临时文件夹（不动真实游戏）

用第 3 节的模拟器游戏：

1. 点「恢复…」：对话框列出这个版本包含哪些部分；「程序」一栏默认「使用本机已有的 Cemu（…）」，下面说和备份的版本是否相同。
2. 选「恢复备份里的 …」，「装到」选 `D:\restore-test\Emu`，「游戏文件放到」选 `D:\restore-test\ROMs`，**取消勾选**最下面的「恢复后让 Ludonimbus 和 Steam 快捷方式指向新位置…」，开始恢复。
3. 完成后：`D:\restore-test\Emu` 里是模拟器（没有存档、没有密钥），`D:\restore-test\ROMs` 里是这个游戏的文件，和原来的逐个文件一致（可以用 `Get-FileHash` 抽查）。Cemu 的更新在 `D:\restore-test\Emu\...\mlc01\usr\title\0005000e\...`。
4. 再用同样的设置恢复一次：提示「… 个已经在本机，没有改动」。
5. 恢复到一半点「停止」，卡片上出现「继续恢复」，点它从断点继续。
6. 测完删掉 `D:\restore-test`。

### 6. 本体缺失后从云端安装（Ludonimbus 里）

不要删游戏，**把游戏文件改个名字**来模拟（测完改回来）：

1. 模拟器游戏：把它的光盘镜像（或游戏文件夹）所在的文件夹改名。重编译游戏：把程序文件夹改名。
2. 详情页卡片显示「本机没有文件」和「从云端安装…」。
3. 点它：模拟器游戏的「程序」默认使用本机已有的模拟器，「游戏文件放到」选一个新文件夹，**保持勾选**修正路径，开始。
4. 完成后：Ludonimbus 里游戏的启动参数指向新位置的游戏文件；从 Ludonimbus 或 Steam 启动能正常玩，存档是最新的。
5. Steam 快捷方式：开了「Steam 自动同步」的不用改；没开的，如果 Steam 开着，卡片显示「更新 Steam 快捷方式」，点它会提示关闭 Steam。
6. 改回去：删掉新恢复的文件，把原文件夹名字改回来，在「游戏位置」或游戏设置里把路径和启动参数改回原来的。

### 7. Steam 插件：从云端安装

需要第 6 节的状态（游戏文件改了名，云端有备份），Steam 插件已经更新、Steam 重启过。

1. Steam 游戏库里打开这个游戏：「开始游戏」栏的 Ludonimbus 状态显示「本机没有游戏文件 · 点击从云端安装」，悬停显示备份的时间、设备和大小（第一次可能先显示原来的状态，几秒后变化）。
2. 点击：Ludonimbus 打开到这个游戏，恢复对话框已打开。
3. 开始恢复后回到 Steam：显示「正在从云端安装 X%」；完成后变回正常的云存档状态。

### 8. 版本和清理

1. 「版本（N）」：每个版本显示时间、设备、大小和包含的部分。默认保留最近 2 个：备份第 3 个版本后最旧的自动删掉。
2. 手动删除一个版本：提示释放了多少空间。**删完后恢复另一个共用同一个模拟器的游戏**，确认它不受影响。
3. 改成「全部」后不再自动删除。

### 9. 其他游戏文件

规则不认识的游戏、或者 ROM 放在别处的：「备份设置 → 其他游戏文件 → 添加文件… / 添加文件夹…」，再「计算大小」：多出的文件算在「游戏文件」里。恢复时它们放到「游戏文件放到」的文件夹里。

### 10. 百度网盘的提示

1. 百度网盘：卡片显示「非会员下载约 80 KB/s：以后恢复 X 预计要 Y」；第一次备份一个游戏时弹出确认框；恢复对话框里也有这条提示。
2. 夸克网盘：不再显示速度提示，也不弹确认框。

### 11. Google Drive

1. 第 2、3、5 节在 Google Drive 上各做一遍；云端硬盘里能看到 `Ludonimbus\gamebackup\chunks` 和 `games`。

### 12. 两台设备（如果有）

1. 电脑 A 备份一个模拟器游戏；电脑 B 上同一个游戏（或「添加游戏 → 来自云端」加进来）从云端安装：模拟器和游戏文件分别选位置，装好能玩，存档是最新的。
2. B 上同一个模拟器的第二个游戏：程序默认使用 B 上已经装好的模拟器。
3. A 正在备份时，B 删除一个版本：提示稍后再清理（不会删掉 A 正在上传的数据）。

### 13. 实测 E1：游戏文件已经在云盘里（v0.4 的准备）

为第 10 节「游戏文件来自云盘里已有的文件」做的实测，不用装应用，但 Ludonimbus 里当前连接的云盘要是被测的那个（测完切回来）。只读你的文件；写的东西都在 `Ludonimbus-E1-…` / `e1-copy-…` 测试文件夹里，最后删除。

```powershell
./scripts/cloud-sources-e1.ps1 -Quark -QuarkFolder "/放游戏的文件夹" -QuarkFile "/放游戏的文件夹/某个 1 GB 以上的文件"
./scripts/cloud-sources-e1.ps1 -Baidu -BaiduFolder "/放游戏的文件夹" -BaiduFile "/放游戏的文件夹/某个文件"
```

- 夸克：能否读你的文件夹、文件带不带哈希、网盘内部复制要多久（大文件几秒完成说明是服务器端复制）。
- 百度：能否读应用目录（「我的应用数据/Ludonimbus」）以外的文件夹、带不带 md5 和下载链接、能否把你的文件复制进应用目录、在应用目录外写入是否被拒绝。

报告在 `%LOCALAPPDATA%\Ludonimbus-e1\`，里面会列出你指定文件夹里最多 10 个文件名，发给我前可以删掉。
