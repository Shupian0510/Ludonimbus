# 0.7 实测清单

> 方案见 [plan-phase5.md](plan-phase5.md)。每做完一步往这里加一节。
> 不要拿真实的存档文件夹做破坏性测试：先在 Ludonimbus 里手动同步一次（云端有一份），或者先把存档文件夹复制一份。

## S0：Switch 存档在 Ryujinx 和 Eden 之间互通

自动测试已覆盖（`crates/core/tests/switch_cross_emulator.rs`）：Ryujinx 的存档恢复进 Eden、Eden 的存档恢复回 Ryujinx、从云端添加时跟随本机的模拟器、按标题 ID 关联云端已有的游戏、同一台电脑不能重复添加。实测要确认的是**真实的 Eden 文件夹结构**，尤其是用户 ID 的写法。

### 准备

- 这台电脑上已有的 Ryujinx，加上 Eden（便携版：解压后在 Eden 文件夹里建一个 `user` 文件夹）。
- 你自己的同一个 Switch 游戏，两个模拟器都能打开（密钥、固件各自装好）。
- Ludonimbus 开发版（我会给你构建好的安装包）。

### 1. Eden 的存档路径（最重要）

1. 在 Eden 里玩一下这个游戏，存一次档。
2. Eden 里右键这个游戏 →「打开存档数据位置」，记下路径，应该形如 `…\user\nand\user\save\0000000000000000\<32 位十六进制>\<16 位标题 ID>`。
3. 在 Steam 里给 Eden 加一个启动这个游戏的快捷方式（启动选项是游戏文件路径），然后在 Ludonimbus 里添加这个快捷方式。
4. 看游戏页的「存档文件」：
   - **应该**：列出第 2 步那个文件夹里的文件，路径显示为 `{nxsave-<标题 ID>}/…`。
   - **如果是空的**：把第 2 步的路径发给我（说明用户 ID 的字节顺序和我按 yuzu 源码推的不一样）。

### 2. 同一台电脑：Ryujinx → Eden

1. 用一个**还没在 Ludonimbus 里添加过**的游戏，先用 Ryujinx 的快捷方式添加，玩一下，同步。
2. 在游戏页点「选择程序…」，选 Eden 的 `eden.exe`（启动选项不变）。
3. 「存档文件」应该变成 Eden 文件夹里的文件；Eden 里还没有这个游戏的存档时是空的。
4. 在「版本历史」里恢复刚才 Ryujinx 上传的版本。
5. 打开 Eden 启动这个游戏：**应该**接着 Ryujinx 的进度玩。
6. 在 Eden 里再存一次档，同步；把程序改回 Ryujinx，恢复最新版本，在 Ryujinx 里**应该**看到 Eden 的进度。

### 3. 从云端添加时跟随本机的模拟器（可选，需要第二台电脑或第二个 Windows 用户）

1. 电脑 A 用 Ryujinx 添加并同步一个游戏。
2. 电脑 B 只有 Eden：在 Ludonimbus「从云端添加」这个游戏，选 Eden 的快捷方式。
3. 游戏页的来源应该显示 Eden；同步后在 Eden 里接着玩。
4. 另一种：电脑 B 直接扫描或添加 Eden 的快捷方式（不选「从云端添加」）。添加后它**应该**自动关联到云端已有的那个游戏（版本历史里能看到电脑 A 的版本），而不是在云端多出一个新游戏。

### 注意

- Eden 在每个存档文件夹里放一个 `.yuzu_save_size`，它不会被同步，恢复时也不会被删掉。
- Eden 里一个用户都没有时，恢复会提示「先打开一次 Eden，建好一个用户」。

## V1：游戏库分清本机有没有游戏

自动测试已覆盖（`games::tests::playable_needs_program_and_game_file`）：没设置程序、程序不在了、模拟器参数里的游戏文件不在了，这三种都算「本机只有存档」。实测要看的是**你游戏库里的真实游戏**被分得对不对。

1. 打开游戏库（网格视图，不分组）。
   - **应该**：本机装着的游戏是彩色的，排在前面；后面一条分隔线「本机没有安装 · N」，下面是灰色的游戏。
   - 灰色的应该是：Ludusavi 扫到但已经卸载的游戏、程序被删掉或移走的游戏、ROM 已经删掉的模拟器游戏。**如果有装着的游戏变灰了，或者卸载了的还是彩色**，把游戏名和游戏页「游戏位置」里的路径发给我。
2. 鼠标移到灰色封面上：提示「本机没有这个游戏，只有它的存档…」。
3. 切到列表视图：灰色的游戏在一行「本机没有安装 · N」下面，图标是灰的。
4. 打开「按来源分组」：每组里灰色的排在最后（分组里没有分隔线）。
5. 显示选项（滑块按钮）里关掉「显示没有安装的游戏」：灰色的都不见了，「全部」后面的数字变少；再打开恢复。重开应用后这个设置还在。
6. 点开一个灰色的游戏：顶部有一条说明为什么是灰色（没设置位置 / 不在原来的位置 / 找不到游戏文件），带「自动查找」。点「自动查找」或「选择程序…」设好位置后，回到游戏库**应该**变成彩色、排到前面。
7. 灰色的游戏点「立即同步」「备份当前存档」照样能用。

## V2：只在云端的游戏

自动测试已覆盖（`crates/core/tests/save_library.rs`）：电脑 A 上传存档和封面后，电脑 B 列出这个游戏、下载同一张封面；B 上的 GOG 版、Xbox 版被认成同一个游戏。实测要看的是界面和真实云盘。

需要第二台电脑，或者同一台电脑上的第二个 Windows 用户（各自装 Ludonimbus、连同一个云盘）。下面叫它们 A 和 B。

1. A：给一个游戏在 Ludonimbus 里选一张封面（游戏页「更换封面」），点「立即同步」。
2. B：打开游戏库。**应该**看到这个游戏是灰色的，排在最后，状态是「只在云端」，封面和 A 选的一样（第一次可能要点一下「刷新」）。
3. B：点开它。**应该**看到「只在云端」的说明、A 上传的存档版本、A 的游戏时间。
4. 断网后重开 B 的 Ludonimbus：灰色的游戏还在（用的是上次取到的列表）。
5. B：点「添加到本机…」→ 选 Steam 快捷方式或程序，或者「先添加（还没装游戏）」。添加后它变成本机的游戏；装着游戏的是彩色，没装的灰色但不再是「只在云端」。
6. （可选，A 备份过这个游戏的本体时）B 上换一个只在云端、有本体备份的游戏，点「从云端安装游戏」：应该进入它的游戏页并打开「从云端恢复」对话框。

## V3：存档库，跨平台应用存档

自动测试已覆盖（同一个测试文件）：按文件名放进 GOG 版、写进 Xbox 版的容器（编号加一、状态改成已修改、清掉「已全部上传」）、从 Xbox 容器读出来再放进 GOG 版；应用前都会存一个「恢复前」版本。实测要看你真实的游戏。

**先备份**：下面会改真实存档。先在 Ludonimbus 里对目标游戏点一次「备份当前存档」；Xbox 版的话，再把 `%LOCALAPPDATA%\Packages\<包名>\SystemAppData\wgs` 整个复制一份。

### 1. 同一个游戏的几个版本显示成一张卡

1. 找一个你同时有两个版本的游戏（比如 Steam 版和 Xbox 版都加进了 Ludonimbus），或者同一个 Switch 游戏的 Ryujinx 和 Eden 条目。
2. 游戏库里**应该**只有一张卡，下面写「2 个版本」。点进去，游戏页顶部「这个游戏的版本」列出两个，点另一个能切过去。
3. 认错了的话点「不是同一个游戏」，它们分成两张卡；认不出来的点「关联其他版本…」选另一个条目，合成一张。

### 2. 你以前手动做过的：Xbox 版 → Steam 版

1. 在 Xbox 版的游戏页「版本历史」里，点某个版本右边的双箭头图标（应用到…），选 Steam 版。
2. 看预览：
   - 写着「从 Xbox 版的存档容器里读出文件」时：核对文件名是不是 Steam 版存档文件夹里的那些名字，目标文件夹是不是 Steam 版的存档文件夹。规则列表里没有这个游戏时会写「按通用规则」，如果名字不对，把预览截图发给我。
   - 写着「按文件名对应」时：说明这个游戏的 Xbox 版存的是普通文件（你以前手动换成功的可能就是这种）。
   - Steam 版在本机还没有存档时会提示先开一次游戏、存一次档。
3. 点「应用」，启动 Steam 版：**应该**接着 Xbox 版的进度玩。
4. 不对的话：Steam 版的「版本历史」里有一个「恢复前」版本，恢复它就回到原样。

### 3. Steam 版 → Xbox 版（实验性）

1. Xbox 版至少要在本机存过一次档（只会替换已有的存档位）。
2. 关掉游戏和 Xbox 应用，在 Steam 版的版本历史里「应用到…」Xbox 版。预览里每个文件右边是「容器名 / 文件名」，没有对应存档位的文件会单独列出来。
3. 应用后先**断网**，从 Xbox 应用启动游戏，看进度对不对，存一次档，再联网。Xbox 问保留哪一份时选这台电脑上的。
4. 把结果告诉我：进度对不对、联网后有没有被换回去。

### 4. 跨平台规则：星露谷物语（Switch ↔ PC）

自动测试已覆盖（`cross_saves.rs`）：Switch 上传的农场和 PC 版认成同一个游戏、按农场文件夹放进 `StardewValley/Saves`（设置文件和别的农场不动）、源存档的游戏版本比目标新时提示、每个版本记下游戏版本、PC 的农场放进 Switch 版的存档数据。实测主要回答两件事：Switch 上的存档根目录是不是直接放农场文件夹；Switch 的主存档文件 PC 版能不能直接读（有教程说是压缩的）。

**准备**：PC 上的星露谷（Steam 版，「添加游戏 → 扫描」加进来）。Switch 那边二选一：Ryujinx / Eden 里的星露谷，或者 Switch 主机上的 Ludonimbus 客户端。两边先各备份一次（Switch 主机用 JKSV）。

1. 两边各同步一次。游戏库里**应该**只有一张星露谷的卡，下面写「2 个版本」。
2. 版本历史里新的版本**应该**显示「游戏 1.6.x」。
3. Switch → PC：在 Switch 版（模拟器条目或 Switch 主机）的版本历史里「应用到…」Steam 版。预览**应该**写「Stardew Valley 在各个平台上的存档是同样的文件」，目标文件夹是 `%APPDATA%\StardewValley\Saves`，文件是「农场名_数字/…」；Switch 的存档比 PC 的新时有黄色提示。应用后开 Steam 版读档，看是不是 Switch 上的进度。
4. 发给我：模拟器里星露谷存档文件夹的文件列表（Ryujinx：右键游戏 → 打开用户存档目录），看农场文件夹是不是直接在里面、有没有别的文件。PC 版读不了 Switch 的存档时，用记事本打开 Switch 那份「农场名_数字」主文件，告诉我开头是正常的 `<?xml` 还是乱码（乱码说明是压缩的，要加一步转换）。
5. PC → Switch：在 Steam 版的版本历史里「应用到…」：
   - 用模拟器时选模拟器里的星露谷，开模拟器读档。
   - 用 Switch 主机时选标着「只在云端」的 Switch 版本。预览**应该**写「存档会叠加到它在云端的最新版本上」，目标是 `nxsave-0100e65002bb8000`，文件是「农场名_数字/…」。应用后半分钟内在 Switch 客户端里刷新，星露谷**应该**显示云端有新版本，下载后开游戏读档。如果下载失败，把客户端的提示告诉我（Switch 存档空间可能不够放 PC 的农场，客户端还不会扩大存档空间）。
6. 不对的话：本机的目标版本在版本历史里有「恢复前」版本，恢复它就回到原样。Switch 主机用准备时 JKSV 的备份恢复；云端原来的最新版本也还在 Switch 版本的历史里。

## H + W：手柄界面和 Windows 掌机

自动测试已覆盖：提示请求文件的读写（`prompt::tests`）、认出掌机的型号（`handheld::tests`）、另一个版本有更新的存档时提示、选「不用」后不再提示（`save_library.rs`）、被强制结束的包装器留下的游戏时间和存档由下一次启动补上（`handheld_catchup.rs`）。下面要你在这台电脑上看。

### 准备

- 一个 Xbox 手柄（有线或蓝牙都行）。
- 一个已经从 Steam 启动、能自动同步的游戏。

### 1. 手柄界面

1. 桌面界面「设置 → 掌机 → 进入手柄界面」。**应该**变成全屏、大字的游戏库。
2. 用手柄：方向键 / 左摇杆移动高亮，A 打开游戏，B 返回，LB / RB 切到设置。高亮要一直看得见。
3. 打开一个游戏：A 是「立即同步」；往下能看到存档版本，A 打开一个版本，可以「恢复这个版本」或「应用到其他版本…」。
4. 有几个版本的游戏（存档库里合成一张卡的），能用手柄切到另一个版本。
5. 设置页的「关闭 Ludonimbus 掌机界面」回到桌面界面。

### 2. 从 Steam 打开手柄界面

1. 「设置 → 掌机 → 加到 Steam」（会关闭并重新打开 Steam）。
2. 打开 Steam 大屏幕模式，在游戏库里找到「Ludonimbus」启动。**应该**全屏显示手柄界面，盖在大屏幕模式上；托盘里的 Ludonimbus 不受影响。
3. 在手柄界面的设置里选「关闭」，回到大屏幕模式。

### 3. 启动游戏时的全屏提示

1. 「设置 → 掌机 → 启动游戏时的提示」选「总是全屏」。
2. 制造一次冲突：断网后玩一下这个游戏（本机有了新存档），然后在另一台设备上给它的云端放一个更新的版本（或者在本机用另一个版本「应用到…」它），再联网从 Steam 启动。
3. **应该**弹出全屏的「存档冲突」，A = 使用云端、X = 使用本机、B = 暂不启动，手柄能选。
4. 改回「自动」，从 Steam **桌面模式**启动：应该是平常的系统对话框；从**大屏幕模式**启动：应该是全屏提示（如果还是系统对话框，告诉我，说明 Steam 没设 `SteamGamepadUI`）。

### 4. 另一个版本有更新的存档

1. 用存档库里合成一张卡的游戏（比如 Steam 版和 Xbox 版），在 A 版本里玩一下并同步。
2. 从 Steam 启动 B 版本：启动前**应该**问「另一个版本有更新的存档，要先应用吗」。选「应用后开始」，进游戏看进度对不对；选「不用」，下次启动不再为同一个存档问。

### 5. （可选）Xbox 全屏体验预览版

1. Windows 设置里打开 Xbox 全屏体验（预览版）。
2. 从 Steam（大屏幕模式）启动 Ludonimbus 和一个游戏，看全屏提示和手柄界面能不能正常显示、操作。
3. 退出托盘里的 Ludonimbus 后再从 Steam 启动、在游戏中途用 Steam 的「停止」结束游戏；再启动并退出另一个游戏，Ludonimbus 的日志（`%APPDATA%\Ludonimbus\logs`）里**应该**有「finishing the session」，第一个游戏的存档和游戏时间被补上。


## L + D：Linux 和 Steam Deck（社区测试）

自动测试已覆盖（Windows 和 Linux 上都跑）：Linux 上的快捷方式包装（启动选项写法、保留原有选项、识别和检查）、`/proc` 进程名、Proton 路径根、模拟器的 Linux 程序名、加到 Steam；后台服务的本地接口在 WSL2 里实际启动过（令牌、拒绝浏览器请求、API 3）。下面要在真机上看，这台电脑测不了，找有 Deck / Bazzite 的人。

1. **安装**：解压 CI 的 `Ludonimbus-linux-x86_64.tar.gz`，运行 `./install-linux.sh`。菜单里有 Ludonimbus；`systemctl --user status ludonimbus-agent` 是 running。
2. **桌面模式**：打开 Ludonimbus，连云盘，添加一个用 Proton 运行的非 Steam 游戏和一个模拟器游戏（AppImage 或 Flatpak），开启自动同步。看 Steam 里这两个快捷方式的启动选项：应该是 `"…/ludonimbus-run" --game <key> -- %command%`，程序没变。
3. **启动**：从 Steam 启动 Proton 游戏，玩一下存档，退出；Ludonimbus 里应该上传了新版本，存档文件路径在 `compatdata/<id>/pfx/drive_c/users/steamuser/…` 下面。

5. **退出游戏**：游戏模式里用 Steam 菜单的「退出游戏」结束，过一会儿再看：存档应该照样上传（包装器接住了 SIGTERM，或者后台服务补传）。
6. **休眠**：游戏中途让 Deck 休眠，醒来后退出游戏，应该能上传（会重试）。

## S1：Switch

自动测试已覆盖（`nx_lan.rs`）：配对（没在配对时、配对码错误都不行）、上报状态、第一次上传建出云端游戏定义、版本列表、下载只含这个游戏的文件、两边都改过时是冲突、移除后令牌失效；HTTPS 证书指纹和 UDP 发现在 WSL2 里实际跑过。

### 电脑这边

1. 「设置 → Switch → 允许 Switch 连接」打开，Windows 防火墙问的时候选「专用网络」。应该显示「已打开」、本机地址和证书指纹。
2. 点「配对新的 Switch」，显示 6 位配对码，5 分钟后自动消失。
3. 关掉开关，状态回到关闭；日志（`%APPDATA%\Ludonimbus\logs`）里有 `listening on port 47716` 和停止的记录。


### Switch 客户端

`ludonimbus.nro` 在本地 `C:\Users\Chiip03\Documents\Projects\Ludonimbus-NX\ludonimbus.nro`，或者 [Ludonimbus-NX](https://github.com/Shupian0510/Ludonimbus-NX/actions) 最新一次构建的 artifact `ludonimbus-nro`。电脑这边要装带「设置 → Switch」的开发版 Ludonimbus（0.6.2 正式版还没有）。

**先备份**：用 emuMMC；先用 JKSV 之类的存档工具把要测的游戏存档备份到 SD 卡。

1. 电脑：「设置 → Switch」打开，点「配对新的 Switch」。
2. Switch：把 `ludonimbus.nro` 复制到 `sdmc:/switch/`，从相册打开（大存档的游戏要按住 R 启动一个游戏，从完整模式进相册）。
3. 选用户 → 列表里应该出现这台电脑（找不到就手动输入电脑上显示的地址）→ 核对 16 位证书指纹和电脑上的一样 → 输入配对码。电脑设置里出现这台 Switch。
4. 列表应该**马上**出来。刚开始有些游戏显示 checking...（电脑在后台向云盘查），几秒内自动变成 not in cloud yet / synced / newer here / newer in cloud / both changed，不用按键。选一个游戏按 A 上传：马上变成 uploading...，电脑传完后自动变成 synced。电脑上的 Ludonimbus 里应该出现这个游戏（只在云端的灰色卡，或者合进电脑上 Ryujinx / Eden 的同一个游戏），版本历史里设备名是 Switch。
   - 上传后马上在 Switch 上退出、甚至关掉 Switch 也可以：电脑会自己传完（电脑日志里有 `uploaded the Switch's version`）。
5. **和模拟器互通**：电脑上用 Ryujinx 或 Eden 添加同一个游戏（已经加过的会自动认成同一个），从 Steam 启动：启动前应该拉取 Switch 的存档，接着 Switch 的进度玩。玩一下退出（自动上传）。
6. 回到 Switch，按 R 刷新：这个游戏应该是 newer in cloud，按 A 下载：屏幕显示「Getting the save from the cloud (N s)」，然后写入。进游戏看进度对不对。
7. **冲突**：Switch 上玩一下、电脑上也玩一下，Switch 刷新后是 both changed。按 A 选 use the cloud's：Switch 的存档先作为备份版本存到云端（电脑的版本历史里能看到），再下载云端的。
   - 再试一次「列表是旧的」：Switch 上玩一下，**先在 Switch 上打开列表**，然后去电脑上玩一下再退出，回 Switch **不刷新**直接按 A。应该弹出冲突选择，而不是直接上传。
8. **恢复**：选一个游戏按 X，选一个旧版本恢复：Switch 上变成那个版本，而且它成为云端最新的版本（电脑上下次启动会拉取它）。
