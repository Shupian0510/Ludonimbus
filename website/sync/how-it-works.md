# 同步怎样工作

Ludonimbus 的同步和 Steam 云存档一样：**启动前拉取，退出后上传**。云端保存的是一个个版本，每个版本是一个只追加、不会被修改的 zip 快照，记录了设备、时间和上一个版本。

## 什么时候同步

| 时机 | 做什么 |
|---|---|
| 从 Steam 启动游戏前 | 云端有较新的版本就拉取下来；有没上传的版本先补传 |
| 游戏和启动器退出后 | 存档有改动就上传一个新版本 |
| 不经过 Steam 直接打开游戏 | Ludonimbus 在托盘里时，发现游戏退出就自动备份 |
| 在 Steam 里点「停止」强制结束 | 托盘里的 Ludonimbus 会发现并立即补传 |
| 点「立即同步」 | 在游戏详情页、或者 Steam 游戏页的同步按钮 |
| 后台 | 每 10 分钟重新检查一次云端，游戏库里的状态随之更新 |

同一个游戏不会同时运行两次同步：界面、托盘的后台监视和 Steam 里的同步按钮共用一把锁。

## 怎么判断该做什么

每次同步，Ludonimbus 比较「上次同步之后，本机变了没有」和「上次同步之后，云端有没有新版本」：

| 本机 | 云端 | 结果 |
|---|---|---|
| 没变 | 没有新版本 | 什么都不做 |
| 没变 | 有新版本 | 拉取云端版本（先保护本机存档） |
| 变了 | 没有新版本 | 上传 |
| 变了 | 有新版本 | **冲突**，两份都保留，让你选择。见[存档冲突](./conflicts.md) |
| 没有存档 | 有版本 | 拉取（例如重装了游戏） |
| 新电脑，第一次同步 | 有版本 | 内容一样就算已同步，不一样算冲突 |
| 连不上云端 | — | 照常启动，上传排队等以后补传。见[离线游玩](./offline.md) |

除了按规则自动清理旧版本，Ludonimbus 不会删除任何版本；自动清理也不会动手动备份、锁定的版本、最新版本和每台电脑上次同步的版本。

## 游戏库里的状态

| 状态 | 意思 |
|---|---|
| 已同步 | 本机和云端一致 |
| 待上传 | 本机有新存档，还没上传 |
| 云端较新 | 其他电脑上传了更新的存档，下次启动前会拉取 |
| 可从云端恢复 | 本机没有存档，云端有 |
| 尚未上传 | 本机有存档，云端还没有 |
| 存档冲突 | 本机和云端都有新改动，需要你选择 |
| 云端离线 | 暂时连不上云端 |
| 未连接云盘 | 还没有在设置里连接云盘 |
| 暂无存档 | 本机和云端都还没有存档 |
| 游戏运行中 | 游戏正在运行，退出后同步 |

## 等游戏真正退出

有些游戏先打开一个启动器，启动器再打开游戏本身，或者游戏退出后还要过一会儿才写完存档。Ludonimbus 会：

- 等游戏**和启动器**都退出后再上传；内置规则里写了游戏真正的进程名，启动器先退出也能认出游戏还在运行。
- 有的游戏在写存档时会留一个锁文件，等它被释放（最多 20 秒）。
- 启动器一直开着的游戏，可以设成「游戏进程退出就上传」，见 [Steam 自动同步](../steam/auto-sync.md#launcher)。

## 一个版本里有什么

每个版本是一个 zip，里面是存档文件本身，加上一份说明：哪台设备、什么时间、为什么上传（例如「退出游戏后自动」「手动备份」），以及上一个版本是哪个。按游戏目录的相对位置记录，所以换了文件夹、换了电脑也能放回正确的位置。

版本怎么查看、恢复和清理，见[版本历史](./versions.md)。
